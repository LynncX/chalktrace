# 板书标注工作台

本地单人标注工具：固定帧集 → OCR 预标注 → 文字和区域修订 → 跨帧身份与版本 → 帧对变化和遮挡 → JSON 导出。与只读的 `../workbench/` 及 `../runs/` 分开，人工数据不由算法运行覆盖。

## 启动

在项目根目录运行：

```sh
pixi run annotate
# 浏览器打开 http://127.0.0.1:8765
pixi run annotate --port 8766
pixi run annotate --help
```

无需新增依赖或数据库，复用 Pixi 中的 Python/OpenCV/PaddleOCR。服务仅监听 `127.0.0.1`；停止用 Ctrl+C。若当前终端继承环境导致 Pixi 报环境编码错误，可用：

```sh
env -i HOME="$HOME" PATH="$HOME/.pixi/bin:/usr/bin:/bin" pixi run --frozen annotate
```

已有试标任务 `whiteboard_pilot`：原视频 140–170 秒，每 5 秒一帧，共 6 帧，全部待标。首次准备时从 `../runs/items_trial_v1/` 导入 150/155/165 秒的 13 个预测框，并对 140 秒原帧单独 OCR。预测在缓存中，不是人工标准答案。

## 操作顺序

- 新建任务：输入项目内视频路径，多行片段 `起点秒,终点秒,间隔秒`。区间右端不包含，按最近原帧号抽取，不经过清晰度筛选。可在创建时输入补充帧 `时间秒,场景 ID`，补充帧单独标记。
- 每个片段初始有独立场景，白板默认全画面。若多个片段共享同一板书场景，在添加条目前于“帧级”面板统一场景；同场景共享白板四角，可用“白板四角”工具调整。片段分组不代表自动检测出了切镜头。
- 选择参考帧：默认同片段前一个标注帧，可改为任何更早的任务帧。帧对标签只指当前选定参考帧，不能直接当成动态门控全部参考对的真值。
- 导入 run：填写运行目录。按相同实际帧号导入 `source_poly` 原图坐标；核验视频元数据和对应原始帧像素，拒绝坐标或原帧不匹配的旧结果。当前预测图层由最近一次导入替换，来源保存在每个预测中；已接受的人工条目不覆盖。无匹配预测的帧可点击“识别当前帧”，在原图上执行 PP-OCRv5，不使用门控。
- 接受预测：点击虚线框或“接受为条目”，核验后勾选“已核验文字、区域与身份”。“加入选中条目”适合 OCR 将一行拆为多框。
- 编辑区域：适配或放大后拖框，选择模式拖动顶点或内部平移。可“重画本行”“添加可见片段”“删除选中区域”。“拆成两行”按输入的原图 y 坐标切开区域，随后分别修订文字和 ID；勾选条目后可合并。拆分与合并不会自动保证文字正确。
- 跨帧：点击参考帧下的条目按钮继承 ID、版本和区域，继承结果全部待确认；也可通过右侧 ID 下拉关联已有条目。“分配新 ID”用于重新书写后的新条目。
- 内容版本：遮挡只改可见状态。追加、部分擦除或重写，点击“新版本”，修订版本文字和当前实际可见文字。修改共享版本文字会使引用该版本的已确认记录重新待确认。
- 遮挡：选择“遮挡多边形”，逐点点击，Enter 完成，Esc 取消。可画多个教师区域、拖顶点修订；帧级面板显示与白板相交的粗遮挡比例。按最大宽度 640 的共同栅格估算并集，不是像素精确分割。
- 完全遮挡：继承既有条目，将可见性设为完全遮挡，会清空可见文字和区域；保留条目身份与已知内容版本。无法辨认用 `[?]`，不从其他帧猜填当前可见文字。
- 帧级核验：填写清晰度、人工 OCR 决策、变化类型和备注，确认没有漏标，再完成本帧。可以保留“不确定”；当前无参考帧时不标帧对变化。完全擦除后后续帧不再保留该条目的可见观察，帧对标擦除；再次书写分配新 ID。
- 回看原视频：展开中间下方的播放器，可定位当前或参考时间，查看采样间发生的事件。回看不会自动增加任务帧；本版帧集在创建后固定，需要补帧时创建包含补充帧的新任务。
- 保存与恢复：修改后自动落盘，Ctrl+S 立即保存。关闭存在未保存内容的页面会提示。支持撤销/重做、JSON 导出及恢复；恢复限同一任务和视频指纹。保存冲突时停止自动覆盖，可先导出本页草稿再重新加载。

快捷键：左右方向键切帧，Ctrl+S 保存，Ctrl+Z / Ctrl+Shift+Z 撤销/重做。输入文字时保留输入框自己的撤销行为。

## 数据格式与清理

- `../evaluation/datasets/<任务>/manifest.json`：视频相对路径、SHA256、尺寸、FPS、原帧号和实际时间、采样片段与帧来源；可进入 Git。
- `../evaluation/annotations/<任务>/annotations.json`：人工场景白板、条目版本、帧观察、明确的参考帧及变化标签；可进入 Git。
- 同目录 `annotations.previous.json`：上一次有效保存的备份，忽略入库。保存采用临时文件、fsync 后原子替换，并使用 revision 拒绝多窗口覆盖。
- `../.cache/annotation/<任务>/`：抽帧 JPEG、`predictions.json`。可清理；“重建图片”先核验视频 SHA256，再恢复原帧，不改人工数据。预测可重新导入或执行 OCR。
- 导出 JSON 包含 dataset 与 annotation，可用于后续评测。当前尚未自动计算 OCR/跟踪准确率；“完成”表示人工完成核验，不代表算法正确。

条目身份由 `(视频 SHA256, 任务 ID, 条目 ID)` 唯一定位，任务内跨帧共用同一 ID。不同任务独立标注，不自动推断跨任务同一条目；如需整批统一身份，应在一个任务中创建全部片段。同一帧的一个条目只出现一次，可拥有多个 `regions`。

核心结构：

```text
annotation
  scenes[S01] = {name, board: 原图多边形}
  tracks[S01-L001] = {scene_id, versions: {V001: 已确认内容文字, ...}}
  frames[F00004500]
    scene_id, reference_id, quality, ocr_decision, events, reviewed, status, note
    occluders: [原图多边形, ...]
    observations: [{id, track_id, version_id, visible_text, regions,
                    visibility, change, confirmed, source}, ...]
```

所有坐标均为原图像素，不随 UI 缩放改变。时间从帧清单读取；内容版本表达板书状态，可见文字表达当前实际观察，两者分开。自动验证几何、引用、视频指纹、同帧 ID 唯一性、完成状态等约束。人工核验仍需确认语义与文字正确性。

## 验证

在项目根目录：

```sh
pixi run python -m unittest discover -s annotation_workbench/tests -v
```

测试使用临时合成视频，覆盖保存/备份/冲突、几何与身份、原帧预标注核验、缓存重建、视频 Range 与本地 API 边界。检测到现有 Node 与 Chrome 时额外执行真实浏览器测试，覆盖改字、完成、跨帧继承、绘框、拆合行、版本、遮挡、撤销/重做及刷新恢复；缺少浏览器则跳过，不安装依赖。

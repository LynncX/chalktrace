# 跨帧条目跟踪

`07` 接收实际 OCR 框与调用记录，`08` 输出去重笔记。默认运行即启用，原有固定采样、变化门控和遮挡门控配置均可使用。

- 在校正板书坐标中匹配行框：横、纵重叠各达到较小框边长的 0.5，同时与条目的末次观察和既有最佳版本比较 NFKC、大小写和标点归一化后的文字；输出仍保留原文。
- 文本相似度至少 0.72；包含关系且短版本至少为长版本的 45% 时允许补全。少于 4 个字符时只允许归一化后完全相等。候选按相似度贪心一对一分配，不将同一次 OCR 中的多个框并入同一条目。
- 最多容许中间缺失 2 次实际 OCR 调用，距末次观察不超过 120 秒。被门控跳过的帧不计作 OCR 缺失；空 OCR 调用计入。超过窗口再出现会创建新条目。
- 先求同条目最高置信度，在距最高值 0.10 内的候选中优先选归一化字符较多的版本，同长度选高置信度。此为启发式完整度选择，不能保证更长的版本更准确；不会把多个版本拼成新句子。
- 每条保留全部观察的 text、score、poly、source_poly、帧号、时间、调用号及输入路径，保存匹配相似度和最佳版本。首末时间仅表示实际观察范围，无法推断真实书写时间、连续可见或擦除时刻。

规则随运行保存为 `07_items/rules.json`，当前不增加 CLI 参数。假定固定机位与固定标定；尚未处理 OCR 行拆分/合并、相机移动和切镜头。相似文字在同位置擦除后重写可能误合并，短词/大幅错字或框跳动可能重复建条目。当前不宣称跟踪精度或笔记准确率提升。

## 运行与核验

```sh
pixi run cv --video data/videos/test_video.mp4 --config evaluation/configs/gate_test_video.yaml --gate-mode occlusion_change --run-id items_trial_v1
pixi run python -m workbench.build --run items_trial_v1 --assets inline
```

- 工作台「条目」展示最佳观察标框、文字裁剪、首末时间及可展开的识别历史。
- `07_items/items.json` 与 manifest.items 使用既有 BoardItem 契约；bbox 为板书坐标下 x/y/宽/高，best.poly 为板书四点，best.source_poly 为原帧四点。
- `07_items/history/<item_id>.json` 保存全部观察和最佳版本；`media/07_items/` 保存实际输入裁剪与映射回原帧的标框。
- `08_notes/notes.md` 按首见顺序输出去重条目，绑定最佳时间和证据链接；`notes.txt` 为纯文本，`raw.md` 保留逐次 OCR 原文。没有执行 OCR 和执行后没有文字分别说明。
- 已有运行产物保持原状；新增阶段需重新运行。

## 验证

```sh
pixi run python -m unittest discover -s cv_engine/tests -q
pixi run python -m unittest discover -s workbench/tests -q
```

测试覆盖重复归并、文本补全、低置信度长版本、同文字不同位置、同位置不同文字、一对一约束、缺失调用与秒数边界、归一化和空结果；流水线测试验证三次观察合为一条、证据存在、时间绑定、去重笔记及工作台渲染。

真实样例结果与残余重复见 [条目验证报告](../evaluation/reports/items_trial_v1.md)。

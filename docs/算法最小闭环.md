# 算法最小闭环

当前闭环执行 `01 抽帧 → 02 区域标定/校正 → 05 增强 → 06 OCR → 08 原文汇总 → 09 运行统计`。未执行的 `03 姿态`、`04 门控`、`07 条目跟踪` 保持 pending。run 的 done 只表示本次最小闭环成功，不代表九阶段全部实现。

## 运行

在项目根目录执行（环境说明见 [算法环境](./算法环境.md)）：

```sh
pixi run cv --help
pixi run cv --video data/videos/test_video.mp4 --config evaluation/configs/minimal_test_video.yaml
# 使用上一步输出的 run_id；展示台与算法分开运行
pixi run python -m workbench.build --run <run_id> --assets inline
```

也可以不使用 YAML：

```sh
pixi run cv --video data/videos/test_video.mp4 --start 120 --end 131 --interval 5 --max-frames 3 --roi 0 18 1280 620
```

CLI 参数覆盖 YAML。默认只取最多 3 个候选帧、每 5 秒取一帧，避免首次运行就对长视频执行大量 CPU OCR。需要增加采样数量时显式调整 `--max-frames`。采样区间为 `[start_s, end_s)`，帧号从 0 开始，时间戳由实际解码帧号 / FPS 计算。`blur_min=0` 默认不筛掉帧；若全部被筛掉则本次运行失败。

`--run-id` 可固定产物目录名；已有目录会被拒绝，防止新旧产物混合。默认自动生成含微秒的运行 ID。运行失败时 manifest 的 run 状态为 failed，对应阶段保留失败说明；阶段状态沿用原契约三态。

## 区域标定与增强

- `roi: [x, y, width, height]`：原帧像素坐标，固定矩形裁剪。
- `corners: [[x1,y1], [x2,y2], [x3,y3], [x4,y4]]`：YAML 指定左上、右上、右下、左下四点，执行透视校正。
- 两者互斥；均未提供时全帧直通，并给出警告，定位成功数为 0。当前没有自动定位算法，也没有随摄像机运动更新标定。
- `enhance: clahe`：灰度 CLAHE，不放大、不二值化；`none` 保留彩色，用于后续对比。校正后彩色图与实际 OCR 输入都落盘。

示例 YAML 中的 ROI 仅适用于当前测试视频。模型默认采用 PP-OCRv5 server 检测和识别，在 CPU 上每次 run 初始化一次并复用；关闭方向辅助模型。默认保留低置信度结果，不用置信度替代识别精度。

## 产物与证据

相对路径以下均以 run 目录为基准：

| 路径 | 内容 |
|---|---|
| `config.yaml` / `manifest.json` | 生效配置、阶段状态、指标与文件索引 |
| `01_frames/frames.json` | 候选帧号、真实时间戳、模糊分数、是否保留 |
| `02_board/calibration.json` | 标定方式、四角、输出尺寸及 source_to_board 矩阵 |
| `media/01_frames/` / `media/02_board/` | 原视频帧、联系表、标定叠加图和校正图 |
| `media/05_enhance/` | 校正后彩色图与无损 PNG OCR 输入 |
| `06_ocr/boxes.json` | 每个框的原文、置信度、poly、source_poly、帧号、时间和输入图路径 |
| `06_ocr/calls.json` / `runtime.json` | 逐次调用结果、推理耗时与模型初始化耗时 |
| `media/06_ocr/` | 原视频帧与映射回原视频坐标的编号框叠加图 |
| `08_notes/notes.md` / `notes.txt` | 按采样时间串联的原文，尚未去重或纠错 |
| `09_stats/summary.json` | 已执行阶段的耗时；manifest 另含进程累计峰值内存 |

`poly` 是校正板书区域坐标；`source_poly` 是通过逆透视矩阵映射到原视频帧的坐标。增强不改变尺寸，所以 OCR 输入和校正图共享坐标系。不能直接把 `poly` 画到完整原视频帧上。

原文汇总不创建伪条目，不调用大模型，不生成 PDF；教师行为统计也尚未实现。自动定位、遮挡门控、跨帧去重及中文板书质量评估是后续工作。

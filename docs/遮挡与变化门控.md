# 遮挡与变化门控

## 使用与对照

在项目根目录运行：

```sh
pixi run cv --video data/videos/test_video.mp4 --config evaluation/configs/gate_test_video.yaml
pixi run python scripts/compare_gate.py --help
pixi run python scripts/compare_gate.py --video data/videos/test_video.mp4 --config evaluation/configs/gate_test_video.yaml
```

配置中的 `gate_mode` 有三种：

- `fixed`：固定采样基线，每个质量筛选后保留的采样帧均执行 OCR；默认行为与原最小闭环一致。
- `change`：只比较变化，没有人体掩码，教师运动也可能触发变化。
- `occlusion_change`：先估计人体覆盖率，再对共同可见区域进行变化比较。

`--gate-mode` 可覆盖 YAML。对照脚本在同一视频、时间区间、帧间隔、ROI、增强和 OCR 参数下分别跑 fixed 与 occlusion_change，再生成两个 run 页面及一个实验对照页；已有输出目录会被拒绝。比较以实际逐帧记录为依据，包含 OCR 次数、人体高覆盖帧的 OCR 次数、推理耗时及各类跳过原因；识别质量尚未自动评测，不把置信度或识别框数当作准确率。

示例配置取 140～165 秒六个采样点，属于探索性验证素材，不是独立测试集。`occlusion_max=0.30`、SSIM 等阈值均未经过人工标注集校准，不能用这一片段断言对其他课堂也有效。

## 人体覆盖估计

使用 [YOLOv8n-pose](https://docs.ultralytics.com/tasks/pose/) 的 ONNX 模型，由 [unileon-robotics 导出仓库](https://huggingface.co/unileon-robotics/YOLO8-ONNX/tree/66e5888954d3454da709847e77b36df31f756aa9) 提供。代码固定下载 revision 与 SHA256，模型在 `../.cache/pose/yolov8n-pose.onnx`，约 13 MB；缓存损坏会明确报错，不继续推理。模型输入为 `[1,3,480,640]`，由现有 PyPI OpenCV DNN 在 CPU 上执行，无需 PyTorch、Ultralytics Python 包或系统安装。

人体框和 17 个关键点位于原视频坐标。将所有人体框通过标定矩阵投影到板书区域，取覆盖并集，按 **并集覆盖像素 / 板书区域像素** 计算覆盖率。分母不是并集，因此不是 IoU；重叠人体不会重复计数。人体框可能包含大量空白，所以这里只是保守估计，不是像素级真实遮挡。检测为空也不能保证无人遮挡。

当前没有识别教师身份、朝向或授课行为。`03_pose/poses.json` 保存检测结果、覆盖率与图片路径；`03_pose/masks/` 保存校正板书坐标系的掩码，`media/03_pose/pose_*.jpg` 保存原帧上的人体框与骨架叠加。

## 门控与参考更新

每帧先检查人体覆盖率，超过阈值直接跳过。其余帧按以下规则判断：

- 没有参考图：放行首个可用帧。
- 距离上次实际 OCR 不到 `cooldown_s`：跳过；时间单位为视频秒数。
- 新露出的区域面积达到 `visibility_gain_min`：保守放行，避免漏掉原先被教师挡住的内容。
- 共同可见区域小于 `common_visible_min`：保守放行，因为缺乏足够依据判为相同。
- 在共同可见区域计算 Gaussian SSIM 与灰度差像素比例，只有 `ssim < ssim_min` 且 `change_ratio >= change_ratio_min` 才按变化放行。
- 达到 `max_gap_s`：周期刷新；这个规则不能覆盖人体高覆盖拒绝。
- 其余帧跳过为 unchanged。

变化比较在最长边 640 像素的灰度图上进行。当前帧和参考图的人体掩码取并集，再将可见区域腐蚀 11×11 像素，避免 SSIM 的 Gaussian 窗口混入被遮挡像素。这里的 SSIM 是共同可见窗口上的均值，不是全图 SSIM。

**参考图只在 OCR 调用成功后更新。** 被遮挡、冷却或 unchanged 跳过的帧不更新参考，也不消费变化。OCR 成功但未识别出文字仍算一次调用，并保留空结果和告警；周期刷新提供再次尝试的机会。门控只决定是否执行整幅校正图 OCR，没有实现分区识别或跨帧条目去重。

## 核验与局限

`04_gate/gate.json` 保存时间、参考时间、覆盖率、SSIM、变化比例、新露出比例、原因和是否放行；`media/04_gate/decision_*.jpg` 保存每个候选帧的决策叠加图。`06_ocr/runtime.json` 分开保存模型初始化与实际 OCR 推理时间。门控计算耗时从 06 阶段耗时中扣除，单独记入 04；总耗时仍由运行开始到收尾实测。

全遮挡时允许 OCR 调用数为 0，不会为获得结果而强行读取遮挡帧，也不会初始化 OCR 模型。笔记页说明未执行 OCR；不据此宣称视频没有板书。

全板覆盖阈值可能让仍有可读局部板书的帧被拒绝；人体框的空白和阴影会影响变化判定。新区域显露会优先补识别，因此仍可能重复读到旧内容。短时出现又擦除的板书、教师持续遮挡、镜头运动以及采样间隔导致的漏检，仍需分区门控、条目跟踪及标注评测解决。

测试覆盖参考提交、遮挡不消费变化、秒级冷却与最长刷新、人体掩码内运动屏蔽、新区域显露、并集覆盖率、全遮挡不加载 OCR、稳定帧减少重复调用。对照页只报告可核验的计算与调用数据；CER、召回和实际误识别变化需后续人工标注。

## 真实变化组件验证

`../evaluation/annotations/gate_pairs.yaml` 显式记录真实视频端点、人工选区、变化类型和预期决策。执行 `pixi run python -m evaluation.evaluate_gate --experiment <新实验名>` 可生成参考帧／候选帧并排证据、标注快照及机读决策。此工具只回放变化组件，假定参考帧已完成 OCR；实际 OCR 调用为 0，不能把策略放行数混同真实调用或识别质量。

当前验证包含三个静态、两个文字新增和一个场景切换样本；真实擦除仍缺失，仅补充了擦除方向的合成单元测试。首轮有一个 ROI 混入教师头顶，已修正标注并保留原结果，未修改阈值。具体结果和边界见 [真实帧对报告](../evaluation/reports/real_gate_pairs_v2.md)。
